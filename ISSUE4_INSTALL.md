# Issue 4 patch: reporting month and row identity

This patch changes only `app/filtered_execution.py` aggregation semantics and adds targeted regression tests.

- Monthly reporting uses the canonical `posting_month` and `posting_date_status` generated by the snapshot cleaner. It does not recompute report month from `POSTING_DATE` or use `REGISTER_DATE__U` for month aggregation.
- `REGISTER_DATE__U` remains in Retrieval Agent registration-month filtering.
- An impossible non-null month (for example `2023-13`) raises `E_INVALID_MONTH`.
- Duplicate or malformed `source_row_id` values cause a structured `RetrievalError`; duplicates are not silently dropped.
- Missing/invalid posting months remain in selected input and are excluded from monthly records with data-quality counts.

## Install
Extract the ZIP at the project root, preserving `app/`, `scripts/`, and `tests/` paths. Then run:

```powershell
python .\scripts\apply_issue4_reporting_identity_patch.py
if ($LASTEXITCODE -ne 0) { throw "Issue 4 patch failed" }
python -m pytest -q
if ($LASTEXITCODE -ne 0) { throw "Tests failed" }
```

The installer backs up the original file as `app/filtered_execution.py.issue4.bak` and refuses to overwrite an existing backup.
