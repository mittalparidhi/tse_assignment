# Fresh-build prompt for a new Lovable account

For a **new, empty** Lovable project: one message that builds the whole dashboard with every fix and feature
from `LOVABLE_PROMPT.md`, `LOVABLE_PROMPT_2.md` and `LOVABLE_PROMPT_TODAY.md`. If credits remain afterwards,
send `LOVABLE_PROMPT_3.md` next for the eight real queries. All numbers are the project's real results;
the before-critique series is from `results/ui/scenarios.json`.

````text
Build a clean, professional, single-page web dashboard in ONE pass. Front end only: React + TypeScript + Tailwind + shadcn/ui + Recharts. No backend, Supabase, authentication, database, payments or external API. All data comes from the local JSON files given at the end (create them exactly). Keep the number of elements small: no hero, no marketing copy, no images, no emojis, no gradients; motion only where described.

## What the app is
"Hyderabad Housing Trends": a multi-agent application that reports how residential asking prices (median ₹ per sq ft) moved over 12 months for user-chosen criteria, plus a metamorphic-testing view of how reliably the system behaves. Data: a frozen snapshot of 99acres.com Hyderabad listings (scraped 26 Aug 2023).

## Visual design
- Fonts (Google Fonts): "IBM Plex Sans" 400/500/600 for ALL text (base 15px, line-height 1.55; page title 20px/600; card titles 15px/600; helper text 13px #5F5F5A). "IBM Plex Mono" 400/500 ONLY for numbers, months, IDs, the SHA and code, with font-variant-numeric: tabular-nums. Body text is never monospace.
- Colours: page #FAFAF7; cards #FFFFFF, 1px #E5E5E0 border, 8px radius; text #1A1A1A; secondary #5F5F5A; one accent #1F5F5B (deep teal) for primary actions and the main chart line. Status: ADEQUATE #2E7D4F, LIMITED #B7791F, NO DATA #9A9A94, violation #B03A2E. Muted badges with a tooltip explaining each in one sentence.
- Layout: top bar (title left; "Frozen snapshot · SHA-256 9e81698…" in mono right). Left sidebar 300px with the criteria form; main area with three tabs: Trend, Relations, Data & method. Max width 1280px. On narrow screens the sidebar becomes a "Criteria" sheet. Visible keyboard focus everywhere; numbers right-aligned in tables; Indian number grouping (₹10,145).

## Sidebar — search criteria
City (Hyderabad, Secunderabad) · retrieval algorithm segmented control "Exact locality" | "Radius" (locality multi-select: Gachibowli, Kondapur, Kokapet, Narsingi, Kollur, Nallagandla, Puppalaguda, Tellapur, Nanakramguda, Financial District; or radius slider 1–40 km default 5 with centre lat/long default 17.4401, 78.3489) · BHK chips 1, 2, 3, 4, 5+ · price band min/max in ₹ lakh with inline validation (min < max) · window end month (2023-03…2023-08, default 2023-08) with "12 months: Sep 2022 – Aug 2023" · display units toggles "₹ lakh / ₹ crore" and "sq ft / sq m" · primary button "Run analysis". With no backend, Run analysis shows a 400ms skeleton and then the saved result, with a muted note "Showing the saved result for 3 BHK · Gachibowli; live runs need the Python service." When a unit toggle changes, fade the changed numbers (150ms) and show a toast: "Display units changed — percentages and rankings are unchanged (relations I2, I5)."

## Tab 1 — Trend (default), from report.json
1. Four stat cards: "Median ₹/sqft move" (yoy_median_psf_pct, signed, 1 decimal; subtitle "between the first and last sufficient month, spans {yoy_span_months} months"); "Listings analysed" (n_price_valid_total; subtitle "{n_listings_total} matched; the rest lack a usable price"); "Coverage" (months ADEQUATE / 12 with a coverage_verdict badge); "Outliers rejected" (n_rejected_outliers; "by the critique feedback loop").
2. Price chart: median ₹/sqft per month, teal line with dots; null months leave a gap; insufficient months hollow dots and lighter line; a dashed vertical marker on the partial month labelled "partial: data to 26 Aug". A "Show before critique" toggle draws before_critique.psf (from report.json) as a dashed grey line under the teal line and lightly shades months where they differ; when on, the first stat card reads "−0.7% (before critique −4.45%, over 3 months)". Under the chart, a bar chart sharing the x-axis: listing_count (grey) and price_valid_count (teal). Hovering a month highlights it in both charts and in the table (shared crosshair). Clicking a month opens a right-side drawer: listings, price-valid, median ₹/sqft in the selected units, coverage status with a one-sentence explanation ("ADEQUATE: at least 30 listings with a usable price"), whether it counts toward the yearly move, and the partial-month note for 2023-08.
3. Monthly table (Month · Listings · Price-valid · Median ₹/sqft · Coverage badge; null as "—") with a "Download CSV" icon button.
4. "Summary" card with the narrative, a "Copy summary" button, and the relaxations as "How your query was widened". Next to it "Most expensive localities" (top 5, numbered).
5. "Agent trace (loops firing)" card: a vertical timeline of trace[] (step number, agent in mono, detail); steps mentioning "cycle 1" tagged "Cycle 1 · coverage → retrieval", "cycle 2" tagged "Cycle 2 · critique → analysis". A "Replay run" button steps through the trace every 0.8s (pause/resume, step slider). Beside the timeline, a small diagram of the six agents (Criteria → Retrieval ×4 → Coverage → Analysis → Critique → Aggregator) with two loop arrows; the active agent's box is highlighted in the accent colour and a loop arrow animates once when its cycle fires. When the replay reaches step 25, morph the price chart from the before-critique line to the final line over 600ms, so the user sees the feedback loop change the answer.
6. "How sure is the headline?" card (label "Whole metro, statistics only"): a slider "Minimum listings for a month to count" over the steps in sensitivity.json (default 50) showing the headline move, span and first sufficient month; a small bar chart of the headline at every step with a horizontal reference line at +6.8% labelled "NHB RESIDEX Hyderabad (official index)"; text: "At 50 the headline is −6.41%; at 75 it is +8.32%, close to the official +6.8%. The threshold, not the data, decides the sign."

## Tab 2 — Relations, from relations.json and relation_details.json
Intro: "Each relation transforms the input, re-runs the system and checks the outputs relate as stated. Unit = base input (72), seeds 11, 23, 47; 95% Wilson intervals." A segmented control "Deterministic" | "With local model (LLM)" | "Compare". Family filter chips (All, Invariance, Monotonic, Directional). Table: ID · Family badge · Transformation · Bases · Violation rate · 95% CI drawn as a thin bar on a 0–1 axis with the interval shaded and a dot at the rate (Compare shows two dots per row: grey deterministic, teal LLM). Rate 0 shows a green "holds"; M1raw gets a grey "counter-example" tag. Clicking a row expands it to show relation, subdomain, tolerance, fault it would expose, and the diagnosis badge when present. Below, verdict cards for relations whose rate is above 0 in the selected mode, showing that mode's rate and verdict.

## Tab 3 — Data & method
- "Data source" definition list from report.json source (SHA in mono, truncated, copy button).
- "Agent architecture": SVG of the six boxes with two accent-coloured curved arrows: "Cycle 1: widen criteria (coverage < target)" from Coverage back to Retrieval, and "Cycle 2: recompute flagged months" from Critique back to Analysis. Under it exactly: **Feedback loop** — "Critique sends a rejection with the flagged months back to Analysis, which recomputes only those months (cycle 2)." **Conditional step** — "Coverage decides whether to stop or to widen one criterion and retrieve again, based on how many months have enough listings (cycle 1)." **Genuine dependency** — "The query mode chooses a different retrieval algorithm: exact locality matching or a geographic radius search."
- "Reproduce": code block with `python scripts/headline_table.py --v2 --check` and `python scripts/replay_llm_sweep.py`.

Code split into small components with a typed data layer (src/types.ts) so the JSON can later come from an API.
````
