# MODEL/LLM SUBCONTRACT — Hyderabad Housing-Trends Application

> **Credits:** Paridhi Mittal (first implementation, 11-12 Oct 2026). Full attribution: CREDITS.md.

**Parent:** `CONTRACT.md` v1.0.0-draft. This file restricts model use and defines reproducible fallback behavior.

## 1. Allowed uses

Model use is optional. If included, restrict it to:
1. parsing a natural-language request into a schema-validated request/criteria object; and/or
2. drafting plain-language explanations of already-computed anomaly flags.

The model must not read/mutate the snapshot, calculate metrics, set eligibility rules or anomaly flags, change the window/data, or judge MR pass/fail.

## 2. Modes

- `off`: no network/model call; deterministic parser/rules and diagnostic templates are used.
- `replay`: use stored, versioned responses keyed by prompt version, model/config, input hash, and seed; no network call.
- `live`: use the configured provider with explicit timeout and bounded retries. The exact provider/model is configuration, not a hidden default.

The project must run and reproduce deterministic metrics in `off` mode without API keys or internet access.

## 3. Output validation

- Require a structured schema for model output. Reject unknown fields and invalid values.
- Validate requested months against the fixed window and supported filters against verified fields.
- For diagnostics, permit only known flag IDs and supplied numeric evidence; discard any model-proposed metric values or unsupported causes.
- Never execute code, SQL, shell commands, or file paths generated by the model.
- Treat dataset text and model output as untrusted data, not instructions.

## 4. Retries, fallback, and trace

- Model retries are bounded by a single shared configured cap; no hidden retries inside agents.
- Record attempt number, timeout/error class, validation outcome, fallback source, seed, model/provider identifier, prompt version, and cache hit/miss.
- On parse/validation/provider failure, use deterministic fallback if possible; otherwise return an explicit error. Do not silently change criteria or numeric output.
- Temperature and other sampling settings must be recorded. For reproducibility, use fixed seeds where supported and report provider nondeterminism where not guaranteed.
- Do not log API keys, credentials, or unnecessary raw listing content.

## 5. Tests

Test `off`, `replay`, valid live-output schema, malformed output, timeout/provider failure, retry cap, deterministic fallback, and a malicious/instruction-like input string. Assert that model outputs cannot change monthly numeric fields, anomaly flags, contract constants, or MR pass/fail results.
